# 需求分析与验收约定

状态：设计已审核，P0–P6 的核心实现与交付整理已完成并分别提交；增强验证仍按约定后置。本文保留题目要求、项目约定和验收口径的区分。

## 1. 依据、优先级与范围

已完整阅读《Java 开发工程师笔试题-文本向量化与检索-v3.3.pdf》全部 3 页，并核对页面图像。下文用“第几页 / 章节”定位原文，不将自行设计的规则归入题目要求。

- **R：题目强制要求**，来自附件的核心需求、功能描述、技术要求和提交要求。
- **B：题目加分项**，来自第四节，原文明确非必须。
- **U：用户本轮要求与暂定技术边界**，不是题目原文。与题目兼容时作为设计约束。
- **D：建议默认规则**，用于补足题目歧义；整体已获审核，以下纳入本轮修订。
- **E：建议扩展**，不进入首版实现验收。

实施顺序为先审核并提交设计，再依次实现、验证和提交 P1–P6。最终交付前另做脚本隔离、意外 worker 退出和文档状态核对；这些收尾验证不改变题目与项目约定的来源分类。

## 4. 歧义、建议默认值与用户建议核对

以下全部为 **D 类本项目约定（已按审核意见修订）**，除明确引用的部分外，不声称来自题目。具体数值均是首版可配置初值，不是性能承诺。

| 编号 | 歧义或用户建议 | 建议默认规则 | 判断及影响 |
| --- | --- | --- | --- |
| D01 | 文档 ID 唯一、重复冲突、不覆盖 | ID 作为主键；任何已有 ID（含失败/失效）重复提交均 409 | 兼容；题目未定义更新或去重规则 |
| D02 | null 与空文本 | text 缺失/null 拒绝；空字符串合法且输出零向量；纯空白按原文向量化，不 trim | 空字符串零向量是 R02；null 与空白处理是补充 |
| D03 | 渠道省略、null、空白 | 入库省略为 default；显式 null/空白/首尾空白拒绝；检索省略渠道表示全部渠道 | default 是 R10；其他细节是补充。不能把“检索未指定”误当仅 default |
| D04 | ID、文本长度与格式 | ID 采用 1–64 个 ASCII 字符、模式 [A-Za-z0-9_-]+，这是本项目约定，并非题目要求；渠道允许中文及其他合法 Unicode 字符，长度 1–64 个 UTF-16 单元，拒绝控制字符、孤立代理项和首尾 Unicode 空白，内部普通空格可保留；大小写敏感、不规范化；文本最多 20,000 个 UTF-16 单元，拒绝孤立代理项；HTTP 请求体上限 256 KiB | 防御性资源边界；不自动截断或规范化原文 |
| D05 | topK、排序相同、候选不足 | topK 必传整数 1–100；不足返回全部；相似度相同按 documentId ASCII 升序；不设最低相似度 | 补充；topK 过大为 400，不静默裁剪 |
| D06 | 零向量余弦未定义 | 任一向量范数为 0 时分数定义为 0；空查询合法，按同分规则返回至多 K 篇并计数 | 已确认保留；会返回零相关结果，示例见下文 |
| D07 | 命中次数定义 | 只给最终 Top-K 每篇 +1；同一请求每篇最多一次；候选扫描不计数 | 用户建议兼容；以服务端成功完成计数事务为口径，非客户端实际收到响应 |
| D08 | 失效与任务完成 | 逻辑失效、不可恢复；重复失效幂等；排队/执行时也允许失效，后台继续完成任务，完成不得改失效字段 | 用户建议兼容；失效不等于取消向量化 |
| D09 | 内存队列满与数据库积压 | 队列容量 1,000；未完成任务最多 10,000；队列满但已持久化仍 202，等待补调度；达到积压上限的新提交返回 503 且不写入 | 补充；区分“已接收待调度”与“服务拒收” |
| D10 | 漏调度与重启 | 1 秒周期补扫 QUEUED；启动把遗留 RUNNING 恢复为 QUEUED；每任务最多实际开始执行 3 次（包含初次执行及被中断的执行），用持久化 attemptCount 限制 | 用户建议兼容；不承诺绝不重复计算，但提交结果原子且有条件 |
| D11 | 检索与失效并发 | 用单实例公平读写锁稳定检索候选；失效提交成功后开始的检索绝不返回该文档；已在执行的检索可先完成并计数，再允许失效成功 | 补充明确线性化顺序；不承诺撤回已发送/在网络中的响应；检索整体预算默认 10 秒，超时/取消清理事务、锁和许可，详见 design §5.3 |
| D12 | 校验错误和执行失败 | 入参错误不创建任务；实际执行异常记录 FAILED，不自动重试；仅进程中断导致未完成任务允许有界恢复；不提供首版手工重试接口 | 符合不无限重试建议；失败 ID 仍占用 |
| D13 | 分页、时间与统计展示 | 列表 page 从 0 开始，size 默认 20、范围 1–100；按 submittedAt 降序再 ID 升序；时间统一 UTC ISO-8601；计数 BIGINT 从 0 开始 | 补充；列表默认包含全部状态和失效文档 |
| D14 | 算法和耗时模拟 | 字符 unigram/bigram 哈希计数、256 维 float、余弦、容量 K 的堆；固定次数 CPU 运算模拟耗时 | 工程选型，非题目指定算法；详见 design.md |
| D15 | 请求失败与计数、数据异常 | Top-K 计数一次事务；确认回滚的临时冲突有限重试，持续不可用降级、提交结果不明不盲重试；失败按类别返回 503；发现坏向量/版本不兼容则整次检索 500 | 结果可解释优先；网络断开与重发可能导致重复计数 |

**空查询示例**：有效且就绪的文档为 A、B、C，初始 hitCount 为 0；请求 `{"text":"","topK":2}`，返回 A、B，score 均为 0，计数变成 A=1、B=1、C=0。若 A 已失效则返回 B、C；渠道过滤先执行，候选不足时不补其他渠道。

**数据库错误口径**：确认整个事务已回滚的锁冲突等临时错误，最多执行数据库事务 3 次（首次+2 次重试），独立于向量化 attemptCount；约束/业务错误不重试。持续不可用进入 not-ready 并暂停新调度，保留进程等待有限探测恢复；提交结果不明确先核对持久化状态，不盲重放命中增量。无法安全消除不确定性时才受控关闭。详见 design §6.4。

用户列出的七条建议均兼容题目。D01、D02、D07、D08、D10、D12 明确了其中尚未定义的边界。数据库恢复、队列补偿和次数上限是可靠性设计，不是附件明文要求。

## 5. HTTP 接口契约草案

所有端点前缀为 `/api`；JSON 使用 UTF-8、字段 camelCase，枚举大写。只接受严格字段类型：数字/布尔值不能强转字符串，浮点数/字符串不能强转 topK；未知字段作为参数错误，避免拼写错误被忽略。路径/查询参数与 JSON 一并验证。下表 URL 是建议设计，并非题目指定。

### 5.1 公共响应对象

**DocumentSummary**：documentId、channel、submittedAt、completedAt（未成功为 null）、vectorReady、invalidated、invalidatedAt（未失效为 null）、hitCount、taskId、taskStatus。

**DocumentDetail**：DocumentSummary 加 text。向量不作为公共接口默认响应；算法和二进制内容通过测试/受控数据库检查验收。

**TaskView**：taskId、documentId、status、createdAt、startedAt（最后一次开始，未开始为 null）、finishedAt（终态时间，非终态为 null）、attemptCount、error（失败时含 code/message，其他状态为 null）、document（SUCCEEDED 时为 DocumentDetail，否则为 null）。失效文档的成功任务仍返回文档，invalidated=true。

**ErrorResponse**：code、message、requestId、details（可选字段级错误列表）。不返回异常堆栈、数据库路径或完整原文；字段错误不回显长文本。

### 5.2 端点定义

| 方法与路径 | 输入、校验 | 成功输出 | 业务异常 |
| --- | --- | --- | --- |
| POST /documents | JSON：documentId、text 必传，channel 可省略；D01–D04 | 202：taskId、documentId、status="QUEUED"、taskUrl；响应表示接收时状态，查询时可能已完成；Location 指向 /api/tasks/{taskId} | 400 参数错误；409 ID 已存在；503 积压满/关闭中/暂不可用 |
| GET /tasks/{taskId} | UUID 格式 | 200 TaskView | 400 非法 UUID；404 任务不存在 |
| POST /search | JSON：text、topK 必传；channel 可省略；D02–D06 | 200：topK、returnedCount、results；每项含 document（DocumentDetail）与 score；空库 results=[] | 400 参数错误；503 并发检索上限/锁等待或整体超时/取消/计数失败；500 向量数据错误 |
| GET /documents | page=0、size=20；可选 channel、invalidated、vectorReady、taskStatus；合法值见 D03/D13 和状态枚举 | 200：items（DocumentSummary[]）、page、size、totalElements、totalPages | 400 非法分页/过滤值；无匹配项为 200 空页，越界页为空 |
| GET /documents/{documentId} | ID 满足 D04 | 200 DocumentDetail | 400 非法 ID；404 文档不存在 |
| GET /documents/{documentId}/task | ID 满足 D04 | 200 TaskView；与按 taskId 查询同一任务 | 400 非法 ID；404 文档不存在 |
| PUT /documents/{documentId}/invalidation | ID 满足 D04；无请求体 | 200 DocumentSummary；重复调用保留首次 invalidatedAt | 400 非法 ID/非空请求体；404 文档不存在；503 锁等待超时/暂不可用 |

检索结果中的 hitCount 是该请求计数事务读取到的值，包含本请求增量；并发请求会继续增长，不代表响应到达时的全局最终值。提交响应不承诺实际入队完成或固定完成时间。

列表 page 必须是非负 int，size 是范围内整数，分页偏移用 long 安全计算；布尔过滤只接受 true/false，taskStatus 只接受下述四个枚举。显式空渠道查询参数非法；未知查询参数同样拒绝。所有查询数据库暂不可用统一 503。

### 5.3 状态和错误码

任务状态：QUEUED=排队中（可能尚未进入内存队列），RUNNING=处理中，SUCCEEDED=完成，FAILED=失败。vectorReady 由成功发布决定；invalidated 是独立维度。

| HTTP | code | 语义与副作用 |
| --- | --- | --- |
| 400 | INVALID_ARGUMENT / MALFORMED_JSON | 缺失、null、格式/类型/范围非法；不创建文档或任务，不计命中 |
| 404 | DOCUMENT_NOT_FOUND / TASK_NOT_FOUND | 合法标识不存在 |
| 409 | DOCUMENT_ALREADY_EXISTS | 包括并发主键冲突；不覆盖、不新增任务；先检查重复，再检查积压 |
| 413 | REQUEST_TOO_LARGE | 原始请求体超过 256 KiB；在 JSON 解析前做字节数限制 |
| 415 | UNSUPPORTED_MEDIA_TYPE | 有 JSON 请求体的端点必须使用 application/json |
| 503 | TASK_BACKLOG_FULL / SERVICE_NOT_READY / SEARCH_BUSY / CONCURRENCY_TIMEOUT / SEARCH_TIMEOUT / SEARCH_CANCELLED / STORAGE_UNAVAILABLE / STORAGE_OUTCOME_UNKNOWN | 未正常完成或提交结果待核对；OUTCOME_UNKNOWN 不承诺回滚。可附 Retry-After，但客户端不得无条件重发有副作用请求 |
| 500 | VECTOR_DATA_INVALID / INTERNAL_ERROR | 数据不兼容、损坏或未分类程序错误；输出 requestId 供排查 |

异步任务失败不会把已返回的 202 变成 HTTP 错误；GET 查询正常返回 200 + FAILED + error。建议任务错误码：VECTORIZE_FAILED、TEXT_DATA_INVALID、RECOVERY_LIMIT_EXCEEDED。业务错误不重试；保存失败状态本身遇到数据库异常时按已确认回滚、持续不可用、提交不明分类处理，详见设计；不是所有数据库错误都退出服务。

## 6. 验收情景与边界

1. 正常提交→获得任务 ID→查询完成→查看文档及元数据→同步检索→命中次数 +1。
2. 暂停 worker，提交仍返回；QUEUED/RUNNING 文档不可检索；失败文档也不可检索。
3. text 缺失/null 为 400；空字符串完成后为 256 个 0；相同文本不同文档得到逐位相同向量；包含 emoji、换行、中文和纯空白。
4. 多请求同时提交同一 ID：恰好一个 202，其余 409，库中一文档一任务。
5. 渠道省略入库为 default；检索省略渠道覆盖所有渠道；指定渠道只在该渠道候选里选 Top-K。
6. K=1、K=100、候选不足、空库、同分、空查询、零向量、非法 K 均有可重复结果。
7. 排队/处理/完成各阶段失效；任务完成后仍保持失效，重复失效不改变首次时间。
8. 两种失效竞争顺序都测试：检索先持读锁则可返回；失效先提交则后续检索不能命中。计数只涉及最终结果。
9. N 次并发检索的 Top-K 总增量与成功计数事务一致；故障注入使事务中途失败时全部回滚。
10. 小容量队列压满后已持久化任务不丢；达到积压阈值后拒收且不产生孤儿记录。
11. 在“提交后入队前”“领取后完成前”“发布事务提交前后”强制结束进程，重启后恢复；终态不重复处理，超恢复次数为 FAILED。
12. 两次真实进程使用同一临时 H2 文件目录，验证文档、向量、状态、失效和计数保留；不是仅用内存数据库代替重启验收。

## 7. 已确认决策与实施记录

- D01–D04：唯一 ID 不可复用、文本空值/空白、渠道和长度限制。
- D05–D07：零向量分数 0，空查询仍返回 Top-K 并计数；同分排序；计数以服务端事务成功为准。
- D08/D11：失效不取消任务；在途检索允许先完成，之后失效才成功。
- D09/D10/D12：已落库任务队列满仍接收；积压阈值拒收；执行失败不自动重试，仅中断恢复，最多开始执行 3 次。

- scheduledIds 所有读写使用同一私有监视器，锁内无数据库/CPU 工作；检索整体预算与取消清理见设计。
